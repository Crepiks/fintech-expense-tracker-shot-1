# Pocket Ledger redesign

Implement the eight supplied desktop/mobile HTML references and PDF as three
responsive views (Calendar, Ledger, Budget) plus quick entry. Preserve version-1
browser data and the existing React/TypeScript/Vite stack. This is a complete
redesign of existing flows; the supplied screens are the accepted visual design.

## Visual system

- Geist for headings and notes; Geist Mono for amounts, labels and controls.
- Background #f4f5f7, white panels, text #13161b, primary #2448c9.
- Category colors: food blue, transport ochre, fun violet, study green,
  health teal, housing near-black, other gray.
- Mobile first: 16px gutters, three summary columns, seven-column calendar,
  grouped ledger rows, compact forecast, fixed bottom navigation and full-screen
  Add. Desktop: 72px header, command trigger, larger calendar and day sidebar,
  tabular ledger, chart and forecast alongside editable category limits.
- No illustrative assets. Keep sample records out of real user storage.

## Implementation sequence

1. Extend version-1 data with optional category limits, fixed markers and recurring
   rules. Test migration, invalid storage, recurrence boundaries, deletion and
   atomic import. Retain storage failure notices and tab synchronization.
2. Add pure command, query and CSV parsers with concrete tests for invalid input,
   money precision, date boundaries, quoting and spreadsheet formula protection.
3. Add pure calendar/forecast calculations; test leap years, past/future months,
   fixed costs, scheduled records, and empty/over-budget states.
4. Compose the app shell and mobile-first Calendar, Ledger, Budget and entry
   surfaces. Provide keyboard navigation, Escape/focus restoration, real editing,
   deletion/Undo, month/week/year navigation and visible empty/error states.
5. Integrate imports/exports, recurring costs and command actions. Add complete
   component/integration tests for each new user flow while retaining domain,
   persistence and validation coverage.
6. Run full enforced coverage, typecheck and production build. Compare desktop
   1280×960 and mobile 390×844 renders to the supplied screens. Check 320px,
   keyboard interactions, reload persistence and console health. Update README,
   screenshots and verification evidence to match the implemented behavior.

## Important behavior decisions

- Live dates and records replace the reference's September sample data.
- Existing categories remain compatible; #transport means Transportation.
- Budget limits remain shared across months, now with optional category caps.
- Fixed costs are explicit flags, never inferred from the Housing category.
- Monthly rules materialize when the app opens or the local day changes; no
  background server is needed or claimed. Removing a rule keeps past records.
- Daily allowance includes today, matching the existing app's documented rule.
- CSV import is validated before any records are added; exports cover the
  selected month. Future entries and pending fixed costs must not be double counted.

## Review focus

Persistence compatibility; duplicate recurring entries after reload/Undo; CSV
formula/quoting errors; forecast treating future records as past; mobile keyboard
and bottom-navigation overlap; search/filter totals; accessible modal focus.
